## Die zwei Hauptansätze
### Ansatz 1: `factory[action](parameter)`
- Object-Style
- gibt ein **Objekt/Dictionary** zurück mit verschiedenen Methoden

### Ansatz 2: `factory(action)(parameter)`
- Curried-Function-Style
- gibt eine **Funktion** zurück, die weitere **Funktionen** zurückgibt

## Konkretes Beispiel: Database-Factory
### Zelle 1 - Object-Style Factory (`db[action](parameter)`)

```python
def erstelle_database_client_object_style(connection_string, db_name):
    """
    Object-Style: Gibt Dictionary mit Methoden zurück
    Verwendung: db["select"](query) oder db["insert"](data)
    """
    
    def connect():
        print(f"🔗 Verbinde zu {connection_string}/{db_name}")
        return {"status": "connected", "db": db_name}
    
    def select(query):
        print(f"📊 SELECT Query: {query}")
        print(f"   Database: {db_name}")
        return {"results": [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]}
    
    def insert(data):
        print(f"💾 INSERT Data: {data}")
        print(f"   Database: {db_name}")
        return {"inserted_id": 123, "success": True}
    
    def update(table, data, where):
        print(f"✏️ UPDATE {table} SET {data} WHERE {where}")
        print(f"   Database: {db_name}")
        return {"affected_rows": 1, "success": True}
    
    def delete(table, where):
        print(f"🗑️ DELETE FROM {table} WHERE {where}")
        print(f"   Database: {db_name}")
        return {"deleted_rows": 1, "success": True}
    
    # OBJECT-STYLE: Dictionary mit Methoden zurückgeben
    return {
        "connect": connect,
        "select": select,
        "insert": insert, 
        "update": update,
        "delete": delete,
        "info": {"connection": connection_string, "database": db_name}
    }

# Object-Style verwenden
print("=== Object-Style Factory ===")

users_db = erstelle_database_client_object_style("mysql://localhost:3306", "users")
orders_db = erstelle_database_client_object_style("postgresql://db:5432", "orders")

print("Users DB Info:", users_db["info"])
print("Orders DB Info:", orders_db["info"])

# Verwendung: object[method](parameters)
users_db["connect"]()
result1 = users_db["select"]("SELECT * FROM users WHERE active = 1")
result2 = users_db["insert"]({"name": "Charlie", "email": "charlie@example.com"})

orders_db["connect"]()
result3 = orders_db["update"]("orders", {"status": "shipped"}, "id = 456")
```

### Zelle 2 - Curried-Function-Style (`db(action)(parameter)`)

```python
def erstelle_database_client_function_style(connection_string, db_name):
    """
    Function-Style: Gibt Funktion zurück, die weitere Funktionen zurückgibt
    Verwendung: db("select")(query) oder db("insert")(data)
    """
    
    def database_action(action):
        """
        Diese Funktion wird zurückgegeben und "erinnert" sich an connection_string und db_name.
        Sie gibt je nach action eine spezialisierte Funktion zurück.
        """
        
        if action == "connect":
            def connect():
                print(f"🔗 Verbinde zu {connection_string}/{db_name}")
                return {"status": "connected", "db": db_name}
            return connect
        
        elif action == "select":
            def select(query):
                print(f"📊 SELECT Query: {query}")
                print(f"   Database: {db_name}")
                return {"results": [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}]}
            return select
        
        elif action == "insert":
            def insert(data):
                print(f"💾 INSERT Data: {data}")
                print(f"   Database: {db_name}")
                return {"inserted_id": 123, "success": True}
            return insert
        
        elif action == "update":
            def update(table, data, where):
                print(f"✏️ UPDATE {table} SET {data} WHERE {where}")
                print(f"   Database: {db_name}")
                return {"affected_rows": 1, "success": True}
            return update
        
        elif action == "delete":
            def delete(table, where):
                print(f"🗑️ DELETE FROM {table} WHERE {where}")
                print(f"   Database: {db_name}")
                return {"deleted_rows": 1, "success": True}
            return delete
        
        elif action == "info":
            def info():
                return {"connection": connection_string, "database": db_name}
            return info
        
        else:
            raise ValueError(f"Unbekannte Aktion: {action}")
    
    # FUNCTION-STYLE: Funktion zurückgeben, die weitere Funktionen zurückgibt
    return database_action

# Function-Style verwenden
print("\n=== Function-Style Factory ===")

users_db_func = erstelle_database_client_function_style("mysql://localhost:3306", "users")
orders_db_func = erstelle_database_client_function_style("postgresql://db:5432", "orders")

print("Users DB Info:", users_db_func("info")())
print("Orders DB Info:", orders_db_func("info")())

# Verwendung: function(action)(parameters)
users_db_func("connect")()
result1 = users_db_func("select")("SELECT * FROM users WHERE active = 1")
result2 = users_db_func("insert")({"name": "Charlie", "email": "charlie@example.com"})

orders_db_func("connect")()
result3 = orders_db_func("update")("orders", {"status": "shipped"}, "id = 456")
```

## Erweiterte Beispiele
### Zelle 5 - Dynamische Actions (Function-Style Vorteil)
```python
def erweiterte_database_function_style(connection_string, db_name):
    """
    Function-Style mit dynamischen Actions - zur Laufzeit erweiterbar
    """
    
    # Basis-Actions
    base_actions = {
        "select": lambda query: f"SELECT {query} FROM {db_name}",
        "insert": lambda data: f"INSERT INTO {db_name}: {data}",
        "delete": lambda where: f"DELETE FROM {db_name} WHERE {where}"
    }
    
    # Dynamische Actions (können zur Laufzeit hinzugefügt werden)
    dynamic_actions = {}
    
    def database_action(action):
        # Basis-Actions prüfen
        if action in base_actions:
            return base_actions[action]
        
        # Dynamische Actions prüfen  
        if action in dynamic_actions:
            return dynamic_actions[action]
        
        # Spezielle Meta-Actions
        if action == "add_action":
            def add_action(name, func):
                dynamic_actions[name] = func
                print(f"✅ Action '{name}' hinzugefügt")
                return f"Action {name} registered"
            return add_action
        
        if action == "list_actions":
            def list_actions():
                all_actions = list(base_actions.keys()) + list(dynamic_actions.keys()) + ["add_action", "list_actions"]
                return all_actions
            return list_actions
        
        raise ValueError(f"Unbekannte Aktion: {action}")
    
    return database_action

print("=== Dynamische Actions (Function-Style) ===")

# Erweiterte DB erstellen
dynamic_db = erweiterte_database_function_style("mysql://server", "dynamic_db")

# Verfügbare Actions anzeigen
print("Anfangs verfügbare Actions:", dynamic_db("list_actions")())

# Neue Action zur Laufzeit hinzufügen
dynamic_db("add_action")("backup", lambda path: f"Backup DB to {path}")
dynamic_db("add_action")("optimize", lambda: "Database optimized")

print("Nach Erweiterung:", dynamic_db("list_actions")())

# Neue Actions verwenden
print("Backup:", dynamic_db("backup")("/tmp/backup.sql"))
print("Optimize:", dynamic_db("optimize")())
```
### Zelle 6 - Builder Pattern mit Object-Style

```python
def query_builder_object_style():
    """
    Object-Style eignet sich gut für Builder-Pattern
    """
    
    def create_builder():
        query_parts = {
            "select": [],
            "from": None,
            "where": [],
            "order": [],
            "limit": None
        }
        
        def select(*fields):
            query_parts["select"].extend(fields)
            return builder  # Fluent Interface
        
        def from_table(table):
            query_parts["from"] = table
            return builder
        
        def where(condition):
            query_parts["where"].append(condition)
            return builder
        
        def order_by(field, direction="ASC"):
            query_parts["order"].append(f"{field} {direction}")
            return builder
        
        def limit(count):
            query_parts["limit"] = count
            return builder
        
        def build():
            # SQL zusammenbauen
            sql = f"SELECT {', '.join(query_parts['select'])}"
            sql += f" FROM {query_parts['from']}"
            
            if query_parts["where"]:
                sql += f" WHERE {' AND '.join(query_parts['where'])}"
            
            if query_parts["order"]:
                sql += f" ORDER BY {', '.join(query_parts['order'])}"
            
            if query_parts["limit"]:
                sql += f" LIMIT {query_parts['limit']}"
            
            return sql
        
        # Builder-Object
        builder = {
            "select": select,
            "from": from_table, 
            "where": where,
            "order_by": order_by,
            "limit": limit,
            "build": build
        }
        
        return builder
    
    return {"create_builder": create_builder}

print("=== Builder Pattern mit Object-Style ===")

query_factory = query_builder_object_style()

# Fluent Interface mit Object-Style
sql_query = (query_factory["create_builder"]()
    ["select"]("name", "email", "age")
    ["from"]("users")
    ["where"]("age > 18")
    ["where"]("active = 1")
    ["order_by"]("name", "ASC")
    ["limit"](10)
    ["build"]())

print("Generated SQL:")
print(sql_query)
```

## Zusammenfassung
### Object-Style: `factory[action](parameter)`

- Gibt **Dictionary/Objekt** mit Methoden zurück
- **Syntax**: `db["select"](query)`
- ✅ **Intuitiv**: Sieht aus wie normale Objekt-Methoden
- ✅ **IDE-freundlich**: Autocomplete funktioniert gut
- ✅ **Builder-Pattern**: Perfekt für Fluent Interface
- ❌ **Speicher**: Alle Methoden werden sofort erstellt, weniger flexibel

```python
db = erstelle_database_client()
db["select"](query)          # Dictionary-Zugriff
db["insert"](data)           # Jede Methode ist sofort verfügbar
db["info"]                   # Metadaten im Dictionary
```

### Function-Style: `factory(action)(parameter)`

- Gibt **Funktion** zurück, die **weitere Funktionen** zurückgibt
- **Syntax**: `db("select")(query)`
- ✅ **Dynamisch**: Actions können zur Laufzeit hinzugefügt werden
- ✅ **Speicherschonend**: Nur eine Funktion wird erstellt
- ✅ **Lazy Loading**: Methoden entstehen erst bei Bedarf
- ❌ **Syntax**: `db("action")(param)` ist ungewöhnlicher

```python
db = erstelle_database_client()
db("select")(query)          # Verschachtelte Funktionsaufrufe
db("insert")(data)           # Action wird erst bei Aufruf "materialisiert"
db("info")()                 # Auch Metadaten sind Funktionen
```
## Praktische Anwendung:
- **Object-Style** → REST-APIs, Query Builder, feste Methodensets
- **Function-Style** → Plugin-Systeme, Event-Handler, dynamische Erweiterungen
