## Worum es geht

Ein langer Essay aus dem Jahr 2012, ausgelöst durch die Programmierkurse der Khan Academy, die auf Processing aufbauen. Victor kritisiert, dass solche Umgebungen nur Code zeigen und Lernende raten lassen, was er bewirkt. Er stellt Anforderungen an eine Programmierumgebung und eine Sprache auf, mit denen man das Programmieren tatsächlich verstehen lernt. Im Archiv lag nur eine Zusammenfassung in den Notizen zu [[Learning p5.js – Notizen zu Learning Processing]], deren Link fälschlich auf einen anderen Artikel zeigte.

## Kernaussagen

- Die Umgebung soll ihr Vokabular erklären, den Ablauf sichtbar machen und den Zustand zeigen.
- Wichtigste Forderung: die Daten zeigen, denn Code verändert Daten, und nur an den Daten sieht man, was er tut.
- Programmieren soll durch Reagieren entstehen – man sieht sofort, was eine Änderung bewirkt, statt alles im Kopf durchzuspielen.
- Abstraktion entsteht, indem man konkreten Code schrittweise verallgemeinert: erst konstant, dann variabel; erst eines, dann viele.
- Die Sprache braucht eine tragende Metapher (die Schildkröte bei Logo, Nachrichten bei Smalltalk), muss Zerlegen und Neukombinieren erlauben und lesbar sein.
- Processings implizite Zustände wie die „aktuelle“ Füllfarbe und sein globaler Zustand erschweren genau das.

## Daraus entstandene Zettel

- [[Eine Lernumgebung muss die Daten zeigen, nicht den Code]]
- [[Abstraktion lernt man, indem man konkreten Code schrittweise verallgemeinert]]
