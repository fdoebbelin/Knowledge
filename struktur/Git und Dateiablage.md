Was Git mit den Dateien macht, die man ihm anvertraut, und wie man Dateien geordnet zwischen Projekten weiterreicht. Erst das Speichern verstehen, dann die Ablage darauf aufbauen. Dazu kommt die Arbeit mit GitHub auf der Kommandozeile.

## Wie Git speichert

- [[Git speichert gleichen Inhalt nur einmal]] – die Prüfsumme als Adresse eines Inhalts
- [[Binärdateien lassen ein Git-Repository schnell wachsen]] – PDFs und Bilder, Größengrenzen, Auswege
- [[Eine gelöschte Datei bleibt in der Git-Historie]] – zurückholen, und warum Löschen keinen Platz schafft
- [[Ein gepushtes Geheimnis muss man austauschen]] – die Folge für Zugangsdaten
- [[Aider macht jede Änderung zu einem Git-Commit]] – die Historie als Sicherheitsnetz für Agentenarbeit

## GitHub auf der Kommandozeile

- [[gh liefert Git das Token für HTTPS]] – wie Git sich über die GitHub CLI anmeldet
- [[Das Konto in gh ist unabhängig vom Konto im Browser]] – die Ursache, wenn ein Push mit dem falschen Konto scheitert
- [[gh repo create bringt ein lokales Repository zu GitHub]] – ein vorhandenes Projekt hochladen
- [[gh repo clone richtet bei Forks ein upstream-Remote ein]] – ein Repository auf den Rechner holen

## Dateien weiterreichen

- [[Ein Austausch-Repository stellt Dateien zu, ohne sie zu bearbeiten]] – die Poststelle als Muster
- [[Eine Quelle löscht man erst, wenn die Kopie geprüft ist]] – verschieben, ohne etwas zu verlieren
- [[Ein Ziffernpräfix sortiert Namen vor die Buchstaben]] – Namen, die verlässlich sortieren
