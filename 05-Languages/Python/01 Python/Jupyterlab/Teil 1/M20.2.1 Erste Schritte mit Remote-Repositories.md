## 1. Remote-Repository Konzept

### Was sind Remote-Repositories?

Remote-Repositories sind zentrale Speicherorte für Git-Projekte, die über das Internet zugänglich sind. Während lokale Repositories nur auf Ihrem Computer existieren, ermöglichen Remote-Repositories die Zusammenarbeit mit anderen Entwicklern und dienen als Backup Ihrer Arbeit.

### Lokales vs. Remote Repository

**Lokales Repository:**
- Existiert nur auf Ihrem Computer
- Alle Git-Operationen sind schnell und offline möglich
- Nur Sie haben Zugriff
- Geht verloren wenn Computer kaputt geht

**Remote Repository:**
- Zentral auf einem Server (GitHub, GitLab, etc.)
- Zugänglich über das Internet
- Mehrere Entwickler können zusammenarbeiten
- Automatisches Backup und Versionierung
- Öffentlich sichtbar oder privat konfigurierbar

### GitHub als Git-Hosting-Service

GitHub ist der weltweit größte Git-Hosting-Service und bietet:
- Kostenlose öffentliche und private Repositories
- Web-Interface für Git-Verwaltung
- Issue-Tracking und Projektmanagement
- Pull Requests für Code-Review
- GitHub Pages für Website-Hosting
- Integrierte CI/CD-Pipelines mit GitHub Actions

**Alternativen zu GitHub:**
- **GitLab:** Open-Source-Alternative mit ähnlichen Features
- **Bitbucket:** Atlassian-Produkt mit Jira-Integration
- **SourceForge:** Einer der ältesten Open-Source-Hosting-Services
- **Codeberg:** Gemeinnützige Alternative für Open-Source-Projekte

## 2. GitHub-Setup und Repository-Erstellung

### GitHub-Account erstellen

**Schritt-für-Schritt Anleitung:**

1. **Website besuchen:** https://github.com öffnen
2. **Account registrieren:** "Sign up" klicken
3. **Username wählen:** Wird Teil der Repository-URL!
4. **E-Mail-Adresse eingeben:** Für Verifikation und Benachrichtigungen
5. **Sicheres Passwort festlegen:** Mindestens 8 Zeichen mit Zahlen/Sonderzeichen
6. **E-Mail-Verifikation abschließen:** Bestätigungs-E-Mail prüfen

### Repository auf GitHub erstellen

**Repository-Erstellung:**

1. **"Create repository"** oder **"+"** Symbol klicken
2. **Repository-Name eingeben:** z.B. "mein-python-projekt"
3. **Beschreibung hinzufügen:** Optional aber empfohlen für Klarheit
4. **Sichtbarkeit wählen:** Public (öffentlich) oder Private (privat)
5. **"Initialize with README" NICHT ankreuzen** (für lokale Projekte)
6. **.gitignore auswählen:** "Python" für Python-Projekte
7. **Lizenz wählen:** Nach Bedarf (MIT License ist beliebt)

**Repository-URL Format:**
```
https://github.com/USERNAME/REPOSITORY-NAME.git
```

### HTTPS vs. SSH Authentifizierung

| Aspekt | HTTPS | SSH |
|--------|-------|-----|
| **Einrichtung** | Sofort einsatzbereit | SSH-Key-Setup erforderlich |
| **Authentifizierung** | Username/Token bei jedem Push | Einmalige Schlüssel-Konfiguration |
| **Sicherheit** | Personal Access Token nötig | Schlüsselpaar-Authentifizierung |
| **Firewall** | Funktioniert überall | Kann blockiert werden |
| **Empfehlung** | Optimal für Anfänger | Für fortgeschrittene Nutzer |

**Für Anfänger: HTTPS wählen** - weniger Konfiguration, sofort nutzbar!

## 3. Git-Remote-Operationen

### Repository mit Remote verbinden

```bash
# Remote-Repository hinzufügen
git remote add origin https://github.com/DozentBWSA/python_kurs.git
```

```bash
# Remote-Konfiguration überprüfen
git remote -v
```

**Wichtige Git-Remote-Befehle:**

- **`git remote add origin <url>`** - Lokales Repository mit Remote verbinden
- **`git remote -v`** - Alle konfigurierten Remote-Repositories anzeigen
- **`git remote remove <name>`** - Remote-Repository-Verbindung entfernen
- **`git remote rename <old> <new>`** - Remote-Repository umbenennen

### Ersten Push durchführen

```bash
# Erster Push mit Upstream-Tracking
git push -u origin main
```

**Was bedeutet `git push -u origin main`?**

- **`git`** - Git-Kommando aufrufen
- **`push`** - Lokale Commits zum Remote-Repository senden
- **`-u`** - `--set-upstream`, verknüpft lokalen Branch mit Remote-Branch
- **`origin`** - Name des Remote-Repositories (Standard)
- **`main`** - Name des lokalen Branches der gepusht wird

**Vorbereitung für ersten Push:**
- Alle Änderungen müssen committed sein
- Remote-Repository muss konfiguriert sein
- Internet-Verbindung muss stabil sein

**Was passiert beim ersten Push:**
1. Lokale Commits werden zum Remote-Repository übertragen
2. Remote-Branch wird erstellt oder aktualisiert
3. Upstream-Tracking wird eingerichtet
4. Zukünftige Pushes sind einfacher mit `git push`

### Pull und Clone Operationen

```bash
# Änderungen vom Remote-Repository holen
git pull origin main
```

```bash
# Repository komplett klonen
git clone https://github.com/username/repository-name.git
```

**Pull vs. Clone - Wann was verwenden?**

**Git Pull:**
- **Zweck:** Aktualisiert lokales Repository mit Remote-Änderungen
- **Wann verwenden:** Wenn lokales Repository bereits existiert
- **Was passiert:** Fetch + Merge in einem Schritt

**Git Clone:**
- **Zweck:** Erstellt lokale Kopie eines Remote-Repositories
- **Wann verwenden:** Für neues Repository oder andere Computer
- **Was passiert:** Komplettes Repository wird heruntergeladen

**Erweiterte Clone-Optionen:**
```bash
# In spezifischen Ordner klonen
git clone https://github.com/user/repo.git mein-ordner

# Nur letzten Commit klonen (schneller)
git clone --depth 1 https://github.com/user/repo.git

# Nur bestimmten Branch klonen
git clone -b main https://github.com/user/repo.git
```

## 4. Kollaboration und Workflow

### Typischer Kollaborations-Workflow

**Schritt-für-Schritt Workflow:**

1. **Repository klonen**
   ```bash
   git clone https://github.com/team/project.git
   ```
   *Ergebnis: Lokale Arbeitskopie erstellt*

2. **Feature-Branch erstellen**
   ```bash
   git checkout -b feature/neue-funktion
   ```
   *Ergebnis: Separater Branch für Entwicklung*

3. **Änderungen entwickeln und committen**
   ```bash
   git add .
   git commit -m "feat: Neue Funktion hinzugefügt"
   ```
   *Ergebnis: Lokale Commits mit Änderungen*

4. **Feature-Branch pushen**
   ```bash
   git push -u origin feature/neue-funktion
   ```
   *Ergebnis: Remote-Branch für Code-Review erstellt*

5. **Pull Request erstellen**
   - GitHub Web-Interface verwenden
   - *Ergebnis: Code-Review und Diskussion möglich*

### Fork-Workflow für Open-Source

**Was ist ein Fork?**
Eine persönliche Kopie eines fremden Repositories auf GitHub, die es ermöglicht, eigene Experimente durchzuführen ohne Auswirkung auf das Original.

**Warum forken?**
- Eigene Experimente ohne Auswirkung auf Original
- Beiträge zu Projekten ohne direkten Schreibzugriff
- Sicherheitsmechanismus für Open-Source-Projekte

**Fork-Workflow Schritte:**

1. Original-Repository auf GitHub forken (Fork-Button)
2. Geforktes Repository lokal klonen
3. Feature-Branch in Fork erstellen
4. Änderungen entwickeln und committen
5. Branch zu eigenem Fork pushen
6. Pull Request vom Fork zum Original erstellen

**Best Practices für Forks:**
- Fork regelmäßig mit Original synchronisieren
- Descriptive Pull Request Beschreibungen schreiben
- Kleine, fokussierte Änderungen bevorzugen
- Projekt-Guidelines und Code-Style beachten

## 6. Praktische Git-Remote-Befehle

### Repository-Status prüfen

```bash
# Aktuellen Status anzeigen
git status
```

```bash
# Remote-Tracking-Information anzeigen
git remote show origin
```

### Synchronisation mit Remote

```bash
# Nur Remote-Änderungen herunterladen (ohne Merge)
git fetch origin
```

```bash
# Remote-Änderungen herunterladen und mergen
git pull origin main
```

```bash
# Lokale Änderungen zum Remote senden
git push origin main
```

### Branch-Management mit Remote

```bash
# Alle Branches (lokal und remote) anzeigen
git branch -a
```

```bash
# Remote-Branch lokal auschecken
git checkout -b lokaler-name origin/remote-branch
```

```bash
# Lokalen Branch zu Remote pushen
git push -u origin feature-branch
```

```bash
# Remote-Branch löschen
git push origin --delete feature-branch
```
