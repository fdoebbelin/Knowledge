## Lernziele
- Kohäsion (Zusammengehörigkeit) in Funktionen und Modulen verstehen
- Kopplung (Abhängigkeiten) zwischen Code-Teilen minimieren
- Code so strukturieren, dass er leicht testbar ist
- Seiteneffekte reduzieren für vorhersagbares Verhalten
- Clean Code Prinzipien praktisch anwenden

## 1. Kohäsion verstehen und verbessern

### 1.1 Niedrige Kohäsion - Problematisches Beispiel
```python
def schlechte_student_verwaltung():
    """Beispiel mit niedriger Kohäsion - macht zu viele verschiedene Dinge"""
    
    # Vermischt verschiedene Aufgaben in einer Funktion:
    # 1. Dateneingabe, 2. Berechnung, 3. Formatierung, 4. Ausgabe
    name = "Anna Müller"
    noten = [1.5, 2.0, 1.8, 2.2]
    durchschnitt = sum(noten) / len(noten)
    
    # Verschiedene, nicht zusammengehörige Aufgaben:
    if durchschnitt <= 2.0:
        status = "Sehr gut"
    else:
        status = "Befriedigend"
    
    # Ausgabe direkt in der Berechnungsfunktion (schlechte Kohäsion)
    ausgabe = f"Student {name}: Durchschnitt {durchschnitt:.2f} - {status}"
    print("WARNUNG: Datei wird überschrieben!")
    
    return ausgabe

print(schlechte_student_verwaltung())
```

```python
def berechne_notendurchschnitt():
```

## 2. Kopplung reduzieren

### 2.1 Starke Kopplung - Problematisches Beispiel
```python
def zeige_starke_kopplung():
    """Beispiel mit starker Kopplung - Funktionen sind zu abhängig"""
    
    # Globale Variable (schlechte Kopplung)
    globaler_rabatt = 0.1
    
    def berechne_preis_mit_starker_kopplung():
        # Abhängig von globaler Variable
        grundpreis = 100.0
        rabatt_betrag = grundpreis * globaler_rabatt
        endpreis = grundpreis - rabatt_betrag
        return endpreis
    
    # Funktion ist an globale Variable gekoppelt
    preis = berechne_preis_mit_starker_kopplung()
    return f"Starke Kopplung - Preis: {preis:.2f}€"

print(zeige_starke_kopplung())
```

### 2.2 Lose Kopplung - Verbesserte Version
```python
def berechne_preis_mit_loser_kopplung():
    """Funktion mit loser Kopplung - Parameter statt globale Variablen"""
    
    grundpreis = 100.0
    rabatt_prozent = 0.1
    
    # Lose gekoppelt durch klare Parameter
    endpreis = grundpreis * (1 - rabatt_prozent)
    return endpreis

print(f"Lose Kopplung - Preis: {berechne_preis_mit_loser_kopplung():.2f}€")
```

```python
def berechne_preis_flexibel():
    """Noch flexiblere Version - alle Werte als Parameter"""
    
    def preis_berechnung(grundpreis, rabatt_prozent):
        """Pure Funktion - nur abhängig von Eingabeparametern"""
        endpreis = grundpreis * (1 - rabatt_prozent)
        return endpreis
    
    # Verschiedene Szenarien testbar
    preis1 = preis_berechnung(100.0, 0.1)  # 10% Rabatt
    preis2 = preis_berechnung(200.0, 0.2)  # 20% Rabatt
    
    return f"Flexibel - Preis1: {preis1:.2f}€, Preis2: {preis2:.2f}€"

print(berechne_preis_flexibel())
```

## 3. Testbaren Code schreiben

### 3.1 Schwer testbarer Code - Seiteneffekte
```python
def schwer_testbare_funktion():
    """Beispiel mit Seiteneffekten - schwer zu testen"""
    
    def verarbeite_bestellung_schlecht():
        # Seiteneffekte: print, Dateizugriff, Zeit
        print("Bestellung wird verarbeitet...")  # Seiteneffekt
        
        # Berechnung vermischt mit Ausgabe
        artikel_preis = 50.0
        anzahl = 3
        gesamt = artikel_preis * anzahl
        
        print(f"Gesamtpreis: {gesamt:.2f}€")  # Noch ein Seiteneffekt
        
        # Rückgabe UND print - inkonsistent
        return gesamt
    
    ergebnis = verarbeite_bestellung_schlecht()
    return f"Schwer testbar - Ergebnis: {ergebnis}"

print(schwer_testbare_funktion())
```

### 3.2 Gut testbarer Code - Pure Functions
```python
def berechne_bestellwert():
    """Pure Function - leicht testbar, keine Seiteneffekte"""
    
    artikel_preis = 50.0
    anzahl = 3
    gesamt = artikel_preis * anzahl
    
    # Nur Berechnung, keine Seiteneffekte
    return {
        'artikel_preis': artikel_preis,
        'anzahl': anzahl,
        'gesamt': gesamt
    }

print(f"Gut testbar - Bestellung: {berechne_bestellwert()}")
```


### 3.3 Seiteneffekte isolieren
```python
def isoliere_seiteneffekte():
    """Demonstration: Seiteneffekte von Logik trennen"""
    
    def berechne_rabatt_logik(grundpreis, kunde_typ):
        """Pure Function - nur Logik, keine Seiteneffekte"""
        
        rabatt_saetze = {
            'standard': 0.0,
            'premium': 0.1,
            'vip': 0.2
        }
        
        rabatt = rabatt_saetze.get(kunde_typ, 0.0)
        endpreis = grundpreis * (1 - rabatt)
        
        return {
            'grundpreis': grundpreis,
            'rabatt_prozent': rabatt * 100,
            'rabatt_betrag': grundpreis * rabatt,
            'endpreis': endpreis
        }
    
    # Logik aufrufen (testbar)
    ergebnis = berechne_rabatt_logik(100.0, 'premium')
    return f"Isoliert - Endpreis: {ergebnis['endpreis']:.2f}€ (Rabatt: {ergebnis['rabatt_prozent']:.0f}%)"

print(isoliere_seiteneffekte())
```

## 4. Clean Code Prinzipien

### 4.1 Selbstdokumentierender Code
```python
def selbstdokumentierender_code():
    """Beispiel für Code, der sich selbst erklärt"""
    
    def berechne_studiengebuehren(semester_anzahl, ist_eu_buerger, hat_stipendium):
        """Berechnet Studiengebühren basierend auf verschiedenen Faktoren"""
        
        # Selbsterklärende Konstanten
        GRUNDGEBUEHR_PRO_SEMESTER = 500.0
        EU_RABATT_PROZENT = 0.2
        STIPENDIUM_ABZUG = 200.0
        
        # Selbsterklärende Berechnungen
        grund_gebuehren = semester_anzahl * GRUNDGEBUEHR_PRO_SEMESTER
        
        if ist_eu_buerger:
            eu_rabatt = grund_gebuehren * EU_RABATT_PROZENT
            grund_gebuehren -= eu_rabatt
        
        if hat_stipendium:
            grund_gebuehren -= STIPENDIUM_ABZUG
        
        # Minimum sicherstellen
        endgebuehren = max(0, grund_gebuehren)
        
        return endgebuehren
    
    # Selbsterklärende Verwendung
    gebuehren = berechne_studiengebuehren(
        semester_anzahl=6,
        ist_eu_buerger=True,
        hat_stipendium=False
    )
    
    return f"Studiengebühren: {gebuehren:.2f}€"

print(selbstdokumentierender_code())
```

### 4.2 Defensive Programmierung
```python
def defensive_programmierung():
    """Beispiel für defensive Programmierung"""
    
    def sichere_durchschnitts_berechnung(noten_liste):
        """Robuste Durchschnittsberechnung mit Eingabevalidierung"""
        
        # Eingabe validieren
        if not noten_liste:
            return {'fehler': 'Keine Noten vorhanden'}
        
        if not isinstance(noten_liste, list):
            return {'fehler': 'Eingabe muss eine Liste sein'}
        
        # Alle Noten validieren
        gueltige_noten = []
        for note in noten_liste:
            if isinstance(note, (int, float)) and 1.0 <= note <= 6.0:
                gueltige_noten.append(note)
        
        if not gueltige_noten:
            return {'fehler': 'Keine gültigen Noten (1.0-6.0) gefunden'}
        
        # Sichere Berechnung
        durchschnitt = sum(gueltige_noten) / len(gueltige_noten)
        
        return {
            'durchschnitt': round(durchschnitt, 2),
            'anzahl_noten': len(gueltige_noten),
            'ignorierte_noten': len(noten_liste) - len(gueltige_noten)
        }
    
    # Test mit verschiedenen Eingaben
    test_noten = [1.5, 2.0, 'ungültig', 1.8, 7.0, 2.2]
    ergebnis = sichere_durchschnitts_berechnung(test_noten)
    
    return f"Defensive Programmierung: {ergebnis}"

print(defensive_programmierung())
```

## Zusammenfassung

### Kohäsion vs. Kopplung:
**Hohe Kohäsion** bedeutet, dass Funktionen und Module zusammengehörige Aufgaben haben. **Niedrige Kopplung** bedeutet, dass verschiedene Code-Teile möglichst unabhängig voneinander sind.

### Testbarkeit erreichen durch:
- Pure Functions (gleiche Eingabe → gleiche Ausgabe)
- Seiteneffekte isolieren
- Parameter statt globale Variablen
- Kleine, fokussierte Funktionen

### Clean Code Merkmale:
- Selbstdokumentierender Code durch aussagekräftige Namen
- Defensive Programmierung mit Eingabevalidierung
- Trennung von Logik und Präsentation
- Konsistente Struktur und Namensgebung
