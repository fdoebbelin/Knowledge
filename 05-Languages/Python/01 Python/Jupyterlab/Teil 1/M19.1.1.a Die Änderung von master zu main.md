**Historisch**: Git verwendete standardmäßig `master` als Default-Branch 
**Seit 2020**: GitHub wechselte zu `main` als Standard für neue Repositories

### Warum der Wechsel?

Der Hauptgrund war die **Umbenennung aus Sensibilität** - viele in der Tech-Community wollten Begriffe vermeiden, die historisch mit problematischen Konzepten assoziiert sind.

## Was ist besser?

**Praktisch gesehen**: Beide funktionieren identisch. Es ist rein eine Benennungsfrage.

**Empfehlung**: Verwende `main`, weil:

- ✅ Es ist der neue Standard bei GitHub, GitLab, etc.
- ✅ Neue Entwickler erwarten es
- ✅ Viele Tools und Tutorials verwenden mittlerweile `main`
- ✅ Es ist inklusiver und zeitgemäßer
- ✅ Vermeidet Verwirrung bei neuen Projekten

## Migration von bestehenden Repos

Falls du ein bestehendes Repository hast:

```bash
# Lokalen Branch umbenennen
git branch -m master main

# Neuen Branch zu GitHub pushen
git push -u origin main

# Default Branch auf GitHub ändern (in den Repository Settings)
# Dann den alten Branch löschen:
git push origin --delete master
```

## Git-Konfiguration anpassen

Für neue Repositories automatisch `main` verwenden:

```bash
git config --global init.defaultBranch main
```

**Fazit**: `main` ist der moderne Standard und praktisch die bessere Wahl für neue Projekte. Bei bestehenden Projekten ist eine Migration sinnvoll, aber nicht zwingend erforderlich.
