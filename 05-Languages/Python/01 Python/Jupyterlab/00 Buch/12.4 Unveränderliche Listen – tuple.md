Tupel sind unveränderliche (immutable) sequentielle Datentypen, die eine beliebig lange Folge beliebiger Elemente aufnehmen können. Im Gegensatz zu Listen können Tupel nach ihrer Erzeugung nicht mehr verändert werden.

## Erstellen von Tupeln

Tupel werden mit runden Klammern erstellt:

```python
a = (1, 2, 3, 4, 5)
a[3]  # 4
```

```python
# Leeres Tupel
leeres_tuple = ()
leeres_tuple
```

```python
# Einelementiges Tupel (benötigt Komma)
ein_tuple = (2,)
type(ein_tuple)  # <class 'tuple'>
```

```python
# Ohne Komma kein Tupel, sondern einfacher Wert
kein_tuple = (2)
type(kein_tuple)  # <class 'int'>
```

## 12.4.1 Packing und Unpacking

### Tuple Packing

Beim Tuple Packing werden mehrere Werte ohne Klammern zu einem Tupel zusammengefasst:

```python
datum = 26, 7, 1987
datum # datum ist (26, 7, 1987)
```

### Tuple Unpacking

Beim Unpacking werden die Werte eines Tupels einzelnen Variablen zugewiesen:

```python
datum = 26, 7, 1987
(tag, monat, jahr) = datum  # Klammern optional
tag # tag ist 26, monat ist 7, jahr ist 1987
```

Werte tauschen ohne Hilfsvariable:

```python
a, b = 10, 20
a, b = b, a
a, b # a ist 20, b ist 10
```

Unpacking funktioniert auch mit anderen sequentiellen Datentypen:

```python
a, b, c = "abc"
a, b # a ist 'a', b ist 'b', c ist 'c'
```

Erweiterte Unpacking-Syntax mit Stern-Operator:

```python
zahlen = [11, 18, 12, 19, 10]
elf, *andere, zehn = zahlen
elf, zehn, andere # elf ist 11, zehn ist 10, andere ist [18, 12, 15]
```

```python
*irgendwas, neunzehn, zehn = zahlen
neunzehn, zehn, irgendwas # neunzehn ist 19, zehn ist 10, irgendwas ist [11, 17, 17]
```

```python
elf, *blablabla = zahlen
elf, blablabla # elf ist 11, blablabla ist [17, 17, 19, 10]
```

Beim Unpacking kann nur eine Referenz mit Stern-Operator verwendet werden, um Mehrdeutigkeiten zu vermeiden.

### Vorsicht bei ungeordneten Datentypen

Bei ungeordneten Datentypen (wie Sets) kann die Reihenfolge nicht garantiert werden:

```python
a, b, c = {3, 1, 2}
a, b, c # Die Zuweisung kann variieren, z.B. a=1, b=2, c=3
```

## 12.4.2 Immutabel heißt nicht zwingend unveränderlich!

Obwohl Tupel selbst unveränderlich sind, können die Werte der enthaltenen Elemente veränderlich sein, wenn es sich um mutable Objekte handelt:

```python
a = ([],)  # Tupel mit einer leeren Liste
a[0].append("Und sie dreht sich doch!")
a # a ist jetzt (['Und sie dreht sich doch!'],)
```

Die Unveränderlichkeit eines Tupels bezieht sich nur auf die enthaltenen Referenzen, nicht auf die Objekte, auf die referenziert wird.

## Hashbarkeit von Tupeln

Da Tupel unveränderlich sind, können Hash-Werte für sie berechnet werden, was sie als Schlüssel in Dictionaries oder als Elemente in Sets verwendbar macht (solange alle Elemente des Tupels ebenfalls hashbar sind).
