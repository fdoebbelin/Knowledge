Erzeugten Code beurteilen kann nur, wer sich selbst vorstellen kann, was er tut: wie sich Variablen ändern, welchen Weg der Ablauf nimmt, was eine Funktion zurückgibt. Ohne dieses innere Modell bleibt als Prüfung nur, ob das Programm scheinbar läuft.

Daraus lässt sich eine didaktische Position ableiten: **erst eine kurze Fundierung ohne KI, dann das Arbeiten mit ihr.** In der ersten Phase üben Lernende Lesen, Nachvollziehen und einfaches Schreiben selbst. Danach wird KI zum Lernpartner, und jeder Vorschlag wird gelesen, erklärt und getestet, bevor man ihn übernimmt. Die erste Phase bleibt bewusst kurz, damit besonders Erwachsene nicht die Motivation verlieren und früh mit aktuellen Werkzeugen arbeiten.

Das ist eine **Position, kein gesichertes Ergebnis**. Es gibt auch den Gegenentwurf, KI vom ersten Tag an einzubeziehen und dafür Zerlegen und Testen stärker zu üben. Die Forschung dazu ist jung, und was für eine Gruppe und eine Kursdauer passt, muss man beobachten.
